The rules that don't bend

Accounting decisions baked into the code, not left to whoever is on the keyboard.

Soft delete

A manager can remove a voucher from lists and totals, with a reason. The row stays in the database and a full snapshot of it stays in the audit log. There is no path in the interface that erases a financial record.

Drafts

An unfinished voucher needs no number, no payee and no lines. It gets its number the moment it is submitted, which is also when full validation runs. Discarding a draft deletes it outright — it was never a committed record.

VAT per line

Amounts are entered excluding VAT and each line is marked VAT-able or not, so one payment can mix fuel at the standard rate with a reimbursement at nothing. A voucher total is always the sum of its lines.

Permissions

Manager, accountant and user — and what each can do is a grid of tick boxes a manager edits at Users → Roles & Permissions. Changes apply to live sessions with no restart. The app refuses to save a grid where nobody can manage users.

Backups

A scheduled LZMA snapshot of the database and every receipt, taken through SQLite's hot-backup API. Restore needs the word RESTORE typed out plus a reason, takes a safety backup first, and screens any uploaded archive for zip-slip and zip-bomb before trusting it.

Documents

Every export is A4 and carries its own sequence — RPT for reports, AUD for the audit log — allocated as it is generated, with the requester's name and the timestamp at the top. Whatever filter is on screen is what lands in the file.

Build

Routes parse the request, services hold every rule with no web framework in sight, templates do the rest. One installer script sets up either path and runs the test suite as its own last check.
